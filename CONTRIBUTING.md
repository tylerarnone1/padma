# Contributing

Thank you for helping make secure defaults easier to reuse.

1. Open an issue for substantial behavior or schema changes.
2. Create a focused branch.
3. Preserve the security invariants in `AGENTS.md`.
4. Add policy and regression tests.
5. Run `npm run check` and `npm run build`.
6. Explain trust-boundary, schema, and dependency changes in the pull request.

Do not combine formatting sweeps with security-sensitive changes. Do not include real credentials, production data, or tokens in issues, fixtures, commits, or screenshots.

Security vulnerabilities belong in the private process described in `SECURITY.md`.
