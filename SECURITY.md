# Security policy

## Supported versions

Until the first stable release, security fixes are applied to the latest
published `0.x` release and the default branch. Upgrade to the newest patch
before reporting an issue that may already be resolved.

## Reporting a vulnerability

Please do not open a public issue.

Use GitHub’s private vulnerability reporting feature for this repository. Include affected versions, impact, reproduction steps, and any suggested remediation. Avoid including real user data or production credentials.

Maintainers should acknowledge a complete report within five business days and coordinate disclosure after a fix is available.

## Scope

Reports about authorization bypass, insecure direct object access, authentication bypass, privilege escalation, secret exposure, webhook signature bypass, SSRF, injection, or unsafe starter defaults are especially valuable.

Downstream applications remain responsible for their product-specific code, infrastructure, provider configuration, and threat model.
